# 产品运营与用户增长诊断工作台

v0.37 · AI辅助诊断交互原型

[打开交互作品集](https://yolanda711.github.io/product-growth-workbench/)

## 工作流程

经营总览 → 专题诊断 → 改进与复盘 → 执行与沉淀。
七个主模块，活动模块内包含四个分页；支持产品筛选、成熟窗口漏斗、改进记录、执行跟进、交接验收与本地备份。

## AI 辅助诊断

- 在经营总览、产品用户旅程和市场券分析页，提供“诊断当前页面”和“生成改进方案”。功能体验、留存与执行页暂未接入专属AI分析，不把主路径指标冒充这些页面的指标。
- 数据事实由工作台计算；生成结果分成原因假设、待补证据、建议行动，保留来源、窗口和筛选范围。
- 默认是明确标注的演示模板，不声称已经调用在线模型。
- OpenAI在线接口代码见 [backend/README.md](backend/README.md)。后端尚未部署、未配置密钥，也未执行真实付费调用；前端的在线模式必须检查后端连接后才能使用，不会以演示结果冒充在线输出。
- 产品建议先审核，再带入待验证改进草稿，补齐项目、负责人、复查日期和基线后由人保存。活动建议可复制或下载，暂不自动写入活动记录。

## 项目边界

使用内置模拟数据，不代表企业实绩。运行时记录属于访问者自己的浏览器，不会自动上传、同步给团队或写回GitHub。原始用户事件、负责人和工作记录不会发送到模型。

这是作品集交互原型，尚无团队登录、共享业务数据库或通知服务。部署后的线上AI调用会产生供应商费用，需要服务所有者配置限额及账号预算。

## 发布与接入

GitHub Pages 从 main 根目录发布 index.html，无需构建。backend/ 独立部署到 Cloudflare Worker，密钥仅保存为后端Secret，严禁提交到公开仓库。
